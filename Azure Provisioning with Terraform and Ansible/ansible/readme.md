# Ansible Automation Layer for Azure VM Configuration

This folder contains the automation logic required to configure a freshly deployed Windows VM in Azure using **Ansible**. It is intended to be used **after Terraform provisioning**, and is triggered via the script `apply-ansible-with-bastion.sh`.

---

## 🚀 Main Components

| File                          | Purpose                                                                 |
|-------------------------------|-------------------------------------------------------------------------|
| `apply-ansible-with-bastion.sh` | Bash script that automates everything: from IP setup to Ansible execution |
| `hosts.ini`                   | Dynamic inventory file used by Ansible (generated by the script)        |
| `main.yml`                    | Ansible playbook that includes all configuration tasks                  |
| `roles/windows_config/tasks/` | Folder containing the actual task files (domain join, hardening, etc.)  |

---

## 🧠 What the Script Does

The `apply-ansible-with-bastion.sh` script:

1. Detects your public IP and applies **temporary, scoped firewall rules** (RDP + WinRM)
2. Attaches a **temporary public IP** to the VM (if needed)
3. Generates a valid `hosts.ini` based on the detected VM IP
4. Executes the Ansible playbook:  
   - Domain join  
   - System hardening  
   - Software installation
5. **Cleans up everything** after execution (firewall rules, IP, etc.)
6. Ensures **Azure Bastion** is deployed for secure future access

---

## 📁 Role Tasks Included

The following task files live inside `roles/windows_config/tasks/`:

- `domain_join.yml` – joins the VM to Active Directory
- `hardening.yml` – applies security settings (includes reboot)
- `software_install.yml` – installs base software (Adobe Reader, etc.)
- `main.yml` – includes all tasks in sequence

You should not run these files individually – always execute from this folder using the script and `main.yml`.

---

## ✅ Notes & Recommendations

- Make sure your DNS and domain settings are reachable from the VM.
- The **local Administrator account is removed** after hardening – ensure domain join worked before that step.
- You can safely re-run the script. It detects existing public IPs and Bastion resources and **won’t duplicate them**.
- Reboot is handled automatically within the playbooks when needed.

---

## 🧰 Prerequisites

- A provisioned VM via Terraform (check the Terraform folder)
- Python 3 + Ansible + required WinRM dependencies
- Network access to AD + domain credentials
